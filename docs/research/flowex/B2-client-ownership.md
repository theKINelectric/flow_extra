# B2 — client ownership (FX-006)

Experiment record, pursuit §3 style. Work package B, second half; design per Astra's consult (codex session `01a0e072`, 2026-09-26).

- **Claim:** the client carries ONE budget from the public entry — queueing and execution share it, the remaining budget reaches the engine instead of a fresh default, a request that expired while queued is refused without invoking callbacks, the one-shot helper process is gone, and the reusable client survives expected request failures, raising them at the caller boundary.
- **Counterexample (audited revision `1e06223`):** `Client.call!` stopped its temporary client only after a successful `GenServer.call` — a caught timeout leaked the helper, linked to the caller (audit probe: `CLIENT_CALL_BANG leaked links alive: [true]`). The persistent client invoked the pipeline with the engine's default deadline, so a longer caller timeout could not reach the work, and an expected pipeline timeout raised inside `handle_call`, taking the client down.
- **Regression:** `test/flowex/client/ownership_test.exs` (+ `test/support/client_ownership_pipelines.ex`); the deadline test's client case repinned from `catch_exit` to a caller-boundary raise. RED at `615559f` — five traps failing. Trap-craft lesson: `self()` inside a spawned caller is the spawned process — build the observing struct in the test process.
- **Fix:** `Client.call/3` computes the absolute deadline caller-side and sends it IN the request envelope; `handle_call` refuses an already-expired request without touching the pipeline, otherwise hands the engine the remaining budget; expected `Flowex.PipelineError`s are rescued into `{:error, e}` protocol replies and re-raised at the caller boundary — the client survives. `Client.call!/3` is direct delegation with the caller's remaining budget; the temporary GenServer is eliminated (accepted presentation change: expected failures raise in the caller instead of exiting through the helper). The outer wait carries a documented 50ms delivery grace so an in-budget refusal reply beats a raw exit; a server busy or gone past deadline + grace still ends the wait the hard way.
- **Boundary cases covered:** queue-expiry refuses without callbacks (200ms occupancy against a 40ms budget, first request's callbacks provably run, queued one's provably never); an 8s budget completes 5.5s of work the engine's old 5s default refused; repeated caught `call!` timeouts leak no links and no late replies.
- **Commands:** `mix test test/flowex/client/` → 4/4 ownership; `mix test --seed 0/42/99/12345` → 96 passed each; format, compile `--warnings-as-errors`, dialyzer (0), credo --strict (0) clean. Runtime: Elixir 1.20.4 / OTP 29.

## Closure addendum (2026-09-27, independent validation)

Two of the six validated violations were the client wrapper's (fixed in `33f2142`):

- **Admission refusals killed the client.** `handle_call` rescued only `PipelineError`; an `AdmissionError` from a full pipeline crashed the client and the caller saw a raw exit. Expected-request treatment now covers it: rescued into `{:error, e}`, re-raised as `Flowex.AdmissionError` at the caller boundary, client alive and reusable (regression: `an overload refusal raises AdmissionError at the boundary and the client survives`).
- **`Client.cast` discarded the engine's refusal.** It was a `GenServer.cast` that fired the engine cast and answered `:ok` unconditionally — the audit's "caller receives :ok for discarded work" surviving inside the wrapper. It is now a `call` returning the pipeline's own answer: `:ok` means admitted-and-accounted, `{:error, :overloaded}` reaches the caller (regression: `Client.cast reports the pipeline's admission refusal`). This makes `Client.cast/2` synchronous — an accepted presentation change, symmetric with the pipeline's own `cast/2` acknowledgment.
